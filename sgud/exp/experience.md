# 累積經驗

本檔為執行工作時特有之累積經驗,留給後續之嘗試、執行與判斷,由agent自行編列、擴充與維護.過長時抽出舊者為`experience_<年月日>.md`,並於本檔註明何時抽出.

## 週期與依時區合併(Gitea #183,2026-11-19)

- **不連外之測試作法**:`test/tools/fakeClock.mjs`以`Date`之子類別取代全域`Date`(無參數之`new Date()`與`Date.now()`取注入之時刻),測試以指定之「現在」執行而不等待;`downloadData`內之`delay(100)`為真實計時器,故每個請求仍耗約100毫秒,13鍵×2時區之案例集合約1分鐘.假交易所以本機`http.createServer`(埠用`listen(0)`)回應合成序列,各欄逐根相異;合併之測試以「逐分鐘合成序列聚合出各原生週期之根」為對照解,不同基底合併之結果須與逐分鐘直接聚合之結果逐位相同.
- **wsemi之`haskey`以`in`判定**:`haskey({}, 'constructor')`為真.舊版`saveData`以之判定週期鍵,`'constructor'`、`'toString'`被當成有效週期鍵,不下載任何分段卻建立同名資料夾(實測).週期表之判定改用自有鍵(`Object.prototype.hasOwnProperty`);同類之判定(任何以`haskey`判定使用者給的鍵者)須注意.
- **dayjs之偏移陷阱**:`dayjs`之`utcOffset`會把絕對值16以內之偏移值當成小時(`+00:15`被當成15小時),舊版對`timeZone: '+00:15'`產出整段位移15分鐘之分段時間(實測).故偏移一律以`Intl.DateTimeFormat(..., { timeZoneName: 'longOffset' })`取得;絕對值小於30分之非零偏移拒絕.
- **舊版之無效時區行為**:`timeZone: 'Bad/Zone'`於建立分段資料夾後才拋原生`RangeError`(殘留空資料夾);新版於任何副作用前拋`invalid opt.timeZone: ...`.
- **交易所原生格線之核實**(2026-11-19,公開行情端點,不帶金鑰):現貨`1d`開於UTC 00:00、`1w`開於週一UTC 00:00、`8h`/`12h`/`6h`/`2h`/`3m`為UTC epoch之整數倍;合約溢價指數之`timeZone`參數不解析(帶`8`、`-5:30`格線不變)、`1s`回400(`-1120`)、`limit=1501`回400;`3d`於現貨與合約溢價指數之開盤對齊不同(現貨2025-11-03、溢價指數2025-11-02).
- **變異測試之作法**:於`./tmp/`之複本植入單一變異後以`mocha --parallel --bail`跑全套,離開碼非0即殺死;每項皆以`quiet-run --lock`逐輪取鎖.等價變異之判準:`aggregateFrom === interval ||`於`!aligned(...)`之前為冗餘(目標自身於此已確知不對齊),已自程式移除而非留作等價變異.
- **測試鎖之飢餓**:測試鎖為輪詢式(無公平佇列),變異harness於每項結束後立即再取鎖,同套件另一排隊者(修前紅、全套)可等逾20分鐘而取不到;全套與修前紅等須先停harness(或以`--only`分段、跳過已完成者)再跑,完畢再續.變異全量約1項/分鐘,94項約95分鐘,須預留.
- **等價對拍之作法**:舊版之`src`複本與現行版於同一行程以假時鐘跑同一序列,假交易所每收一個請求使假時鐘前進40毫秒(令`timeBudget`之行為確定),逐步比對請求(全部查詢參數與回應時刻)、檔案(內容與修改時間)、回傳值、console輸出.
