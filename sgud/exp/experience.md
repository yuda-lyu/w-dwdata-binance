# 累積經驗

本檔為執行工作時特有之累積經驗,留給後續之嘗試、執行與判斷,由agent自行編列、擴充與維護.過長時抽出舊者為`experience_<年月日>.md`,並於本檔註明何時抽出.

## 週期與依時區合併(Gitea #183,2026-11-19)

- **不連外之測試作法**:`test/tools/fakeClock.mjs`以`Date`之子類別取代全域`Date`(無參數之`new Date()`與`Date.now()`取注入之時刻),測試以指定之「現在」執行而不等待;`downloadData`內之`delay(100)`為真實計時器,故每個請求仍耗約100毫秒,13鍵×2時區之案例集合約1分鐘.假交易所以本機`http.createServer`(埠用`listen(0)`)回應合成序列,各欄逐根相異;合併之測試以「逐分鐘合成序列聚合出各原生週期之根」為對照解,不同基底合併之結果須與逐分鐘直接聚合之結果逐位相同.
- **wsemi之`haskey`以`in`判定**:`haskey({}, 'constructor')`為真.舊版`saveData`以之判定週期鍵,`'constructor'`、`'toString'`被當成有效週期鍵,不下載任何分段卻建立同名資料夾(實測).週期表之判定改用自有鍵(`Object.prototype.hasOwnProperty`);同類之判定(任何以`haskey`判定使用者給的鍵者)須注意.
- **dayjs之偏移陷阱**:`dayjs`之`utcOffset`會把絕對值16以內之偏移值當成小時(`+00:15`被當成15小時),舊版對`timeZone: '+00:15'`產出整段位移15分鐘之分段時間(實測).故偏移一律以`Intl.DateTimeFormat(..., { timeZoneName: 'longOffset' })`取得;絕對值小於30分之非零偏移拒絕.
- **舊版之無效時區行為**:`timeZone: 'Bad/Zone'`於建立分段資料夾後才拋原生`RangeError`(殘留空資料夾);新版於任何副作用前拋`invalid opt.timeZone: ...`.
- **交易所原生格線之核實**(2026-11-19,公開行情端點,不帶金鑰):現貨`1d`開於UTC 00:00、`1w`開於週一UTC 00:00、`8h`/`12h`/`6h`/`2h`/`3m`為UTC epoch之整數倍;合約溢價指數之`timeZone`參數不解析(帶`8`、`-5:30`格線不變)、`1s`回400(`-1120`)、`limit=1501`回400;`3d`於現貨與合約溢價指數之開盤對齊不同(現貨2025-11-03、溢價指數2025-11-02).
- **變異測試之作法**:於`./tmp/`之複本植入單一變異後以`mocha --parallel --bail`跑全套,離開碼非0即殺死;每項皆以`quiet-run --lock`逐輪取鎖.等價變異之判準:`aggregateFrom === interval ||`於`!aligned(...)`之前為冗餘(目標自身於此已確知不對齊),已自程式移除而非留作等價變異.
- **測試鎖之飢餓**:測試鎖為輪詢式(無公平佇列),變異harness於每項結束後立即再取鎖,同套件另一排隊者(修前紅、全套)可等逾20分鐘而取不到;全套與修前紅等須先停harness(或以`--only`分段、跳過已完成者)再跑,完畢再續.變異全量約1項/分鐘,94項約95分鐘,須預留.
- **等價對拍之作法**:舊版之`src`複本與現行版於同一行程以假時鐘跑同一序列,假交易所每收一個請求使假時鐘前進40毫秒(令`timeBudget`之行為確定),逐步比對請求(全部查詢參數與回應時刻)、檔案(內容與修改時間)、回傳值、console輸出.

## 重試、暫無數據與缺根(2026-11-19)

- **交易所之「沒有該根」之形式**(公開端點實測):上市前、未來之區間、已下架之交易對之舊區間外,皆為HTTP 200而缺根(整段者為空陣列);錯誤回應只見於參數錯誤(400:`-1100`、`-1120`、`-1121`、`-1130`).現貨ETHUSDT與BTCUSDT之4h於2020-02-19 12:00(UTC)缺1根(兩次查詢相同),溢價指數自2019-12-24起無缺根.故有效觀察以「200而缺根」為主,4xx/5xx之有效觀察是為交易所改以錯誤表示暫不可得時預留,以「確認可達」與次數、天數防誤標.
- **時間換算會取「現在」**:dayjs之`tz(字串或毫秒, 時區)`內部會呼叫無參數之`new Date()`;多做一次換算即多取一次現在.以「每次取值前進」之假時鐘對拍時,這會令其後之修改時間錯開;故請求皆成功且無紀錄檔時不多做時間換算(段之起訖毫秒取自下載函數之回傳、合併時缺根之成因只在`gap`時才算、tag之換算改用已載入之路徑).
- **等價對拍之作法(對1.0.61)**:基準之`src`複本與修改版於同一行程,以解析鉤子把裸名匯入導向同一份相依,並把`wsemi/src/delay.mjs`導向立即完成之替身(兩版同時替換);假時鐘有「凍結」與「每次取值前進1秒」兩種(後者驗兩版取「現在」之次數與順序相同);假交易所各週期完整無缺根、含形成中之末根.每條鏈7步(首抓、同時刻再抓、前進一根、竄改後再抓、乾跑、前進式時鐘加`timeBudget`、前進3天),每步比對請求、回傳(含拋錯)、console輸出、整個輸出樹(檔名清單、內容之sha256、修改時間).工具本身以「多寫一檔」「修改時間多1毫秒」「多印一行」「多取一次現在」四種變異驗過皆判為不同.基底分段因`timeBudget`留待下次而缺時,`aggregate.missing`之`gap`元素多了成因欄,屬可見差異(另計).
- **重試之測試不真的等**:等待一律經`src/timers.mjs`之`sleep`,測試於`before`替換為記錄毫秒數之函數、`after`還原;逾時之測試讓假交易所不回應(於`afterEach`結束其回應)並給小的`timeRequest`.
- **可達不以時間端點補認**:時間端點只證明主機可達,不證明K線端點之路徑與參數正確;以之補認時,端點路徑打錯(一律404)7天後整段期間被標為缺根且改正後不再下載(實測).改為只認同一K線端點於本次對別段之2xx陣列;只下載單一分段而回錯誤者留在暫無數據.
- **紀錄檔損毀而JSON合法**:`firstValid: null`會令相隔之計算成為「現在 − 0」而提早標註、非時刻之字串會令寫回時之`toISOString`拋錯;故讀取時逐範圍檢查(時刻、次數、格點、段內、`n`與起訖一致、不重疊、檔案大小),不合格者整檔視為無紀錄.
- **成因欄只在有資訊時附**:缺之基底根全為「尚未嘗試」(`timeBudget`留下之段、分段檔殘缺列)時附成因欄會破壞與既有回傳之逐位相同,故不附.
- **對拍另比請求標頭**:以`http.Server.prototype.emit`之`request`事件記錄各請求之標頭(去`host`)逐請求比對;修改版改了axios之設定(`signal`、`validateStatus`)而標頭須不變.

## 紀錄檔改為每資料夾一個(2026-11-19,Gitea #192 修正輪)

- **為何每資料夾一個**:小週期(`1m`每段1小時)且`dayStart`遠早於上市時,每段一檔會有數萬個小檔,每輪讀檔(且舊制於迴圈內與回傳前各讀一次)之成本不可忽略;同資料夾本即單一寫入者.改後每次執行讀一次、有變動才以暫存檔再改名覆寫;各範圍帶所屬分段`tag`,範圍不跨分段合併.
- **按分段惰性展開**:全檔展開為逐根會建出大量物件(`1m`上市前整段60根×4萬段=數百萬個);故以`tag`分組保存範圍,只有本次需要更新之分段才展開(`barsOf`),完整性判定(`summary`)與合併成因(`recAt`)直接由範圍算(不展開),未更動分段之範圍原樣寫回(含時間字串,免得重新換算).
- **dayjs 時區換算之成本(實測,50,000次)**:`ot.tz(字串, 時區)`約21微秒,`.format()`約113微秒.故讀取時之逐範圍檢查以算術判定(格線:`(o − 錨點) mod 週期 = 0`;分段內:`o ≥ 段起點 且 末根 ≤ 段起點 + 名目長度 − 1秒 + 餘裕`;`n`過大即不合格,不逐根展開),`n`為1且`to`與`from`同字串者免解析`to`;寫入時沿用檔內既有之`from`、`to`字串(`memo`),只對新根換算.
- **大檔之實測成本**:`1m`自2020-01起全為上市前(每段一個範圍、每段60根):43,800個範圍(13.3MB)讀入加逐範圍檢查約3.6秒、81,000個範圍(24.6MB)約6.8秒(每範圍約83微秒,由tag、from、to三次時區解析主導);`list`12毫秒;更動一段後存檔約81毫秒.本案未做行程內之快取(紀錄檔內容不變時略過驗證,可依內容雜湊),列為已知缺口(見`sgud/state/state.md`).
- **檔案上限64MiB之由來**:最壞為`1m`自2017年至今約8萬個分段全為上市前,每段一個範圍約27MB;取2倍餘.上限過小之代價是合法檔被丟棄、累計歸零(須重新觀察至少7天),故寧大勿小;另以大括號之數量(每個合法範圍至少約150位元組)於`JSON.parse`前擋下以空物件灌滿之檔(未超過上限之64MiB全為`{},`約2,100萬個物件,估計記憶體過大).
- **跨日光節約回撥之分段比名目長1小時**(探測:`Europe/London`、`America/St_Johns`、`America/New_York`之直接下載):分段起訖為線性之牆鐘字串(`vt.add(n, 'hour').format(...)`以起點之偏移格式化),再以時區解析為實際時刻,故跨回撥者實際49小時(名目48)、跨春進者47小時.紀錄檔檢查之分段上界須給餘裕(實作取2小時),否則該段最末一小時之根缺時整個資料夾之紀錄檔不合格而每輪重新累計、永遠無法標註(複審所發現,附件原樣亦有).回撥重複之一小時內之牆鐘字串往返可能錯置一小時,為既有限制.
- **兩個不同之tag字串可解析為同一時刻**:夏令時間春進之不存在時刻(如`America/New_York`之`2026-03-08T02:00:00`與`03:00:00`皆為07:00Z),故全檔不重疊之檢查不能只看同tag.
- **整數類選項之檢測**:以wsemi`iseint`判定(`use: 'count'`用於次數、`use: 'timer'`用於計時毫秒,上限2147483647——超過者`setTimeout`改以1毫秒觸發,等於不等待;`timeRequest`另`min: 1`);`noDataTimes`與`timeNoData`不用`use`(安全整數即可,以極大之次數表示「不標註」為合法用法).轉換自行做(`Number(v.trim())`,`-0`以0計)而非`cint`(四捨五入,會把`1.5`收成2).
- **決定資料口徑之opt與執行參數之分野**:`noDataTimes`、`timeNoData`給了而無效即拋(錯值會令資料被永久標註為缺根而靜默缺漏);`retryTimes`等為執行參數,無效改用預設(最壞為多等或少試,不改資料).
- **分類**:`counted`之`httpError`須為4xx/5xx(`httpStatus >= 400`);3xx等非2xx(代理之轉址頁面)不算觀察.
- **對拍工具入庫**:`test/tools/parity.mjs`(假交易所、固定與前進式兩種假時鐘、基準版與現行版於同一行程依序各跑、比對請求(含標頭)、輸出樹、console、回傳);`--mutate`驗證工具本身(多寫一檔、多一個標頭、多一個查詢參數、多印一行、修改時間多1毫秒、多取一次現在、回傳多一鍵,皆判為有差異).易錯處:擷取console須先於植入「多印一行」之變異(否則該行不被擷取而判為無差異);輸出中含各版自己之資料夾之絕對路徑須先換為`<ROOT>`;`delay(100)`(2xx後之頻率節制)於工具內改為立即(兩版相同,只為縮短時間).基準版之取得:`git archive HEAD src`解到`./tmp/`之下(相依由上層`node_modules`解析).
- **子行程(Agent工具)之複審**:唯讀、只給契約與新舊碼位置、不給結論;發現之缺陷:`to`與`n`之檢查於`n>1`而`to`與`from`同字串時漏網、日光節約之分段上界、`noDataTimes`之上限不合理、`httpError`含3xx;皆已修並補測試(`unit-gaps` U8、U12;`api-saveDataGaps` S9e).
- **變異測試之作法**:逐項於`tmp/`之複本植入單一變異(`find`於行尾正規化為LF後須於該檔恰出現一次,否則報ANCHOR-ERROR,不靜默不變異),以`quiet-run --lock`跑相關測試檔(`--bail`),離開碼非0即被殺死.易錯處:`find`須避開多處出現之短字串(`netFails = 0`有兩處,須帶上下文);結果以jsonl追加,重跑時以最後一筆為準.
